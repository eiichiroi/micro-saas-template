## 2. 障害対応

### 手順

1. **検知：** 〔エラー監視の通知、ユーザーからの連絡〕
2. **影響の確認：** 全員か一部か。決済・ログイン・データに影響があるか
3. **応急処置：** 〔直前のデプロイを戻す、機能を止める、など〕
4. **ユーザーへの連絡：** 影響が大きければ〔ステータスページ／メール／X〕で知らせる
5. **原因の調査と恒久対策**
6. **振り返り：** 下の記録に追記する

### 重大度の目安

| 重大度 | 状態 | 対応の目安 |
|---|---|---|
| 高 | 決済ができない、データが消える・漏れる、全員が使えない | すぐに対応し、ユーザーへ連絡する |
| 中 | 一部の機能が使えない、一部のユーザーだけ影響 | 当日中に対応する |
| 低 | 見た目の不具合、回避策がある | 通常の開発で直す |

### ロールバック

- 〔直前のバージョンへ戻す手順。コマンドや画面の操作を具体的に〕
- 〔DB のマイグレーションを戻す場合の注意〕

### データの復元

- 〔バックアップからの復元手順〕
- 〔最後に復元を試した日：YYYY-MM-DD〕

### 個人情報・秘密情報の漏えいが疑われるとき

1. 該当するキー・パスワードをすぐに無効化し、再発行する
2. 影響範囲を確認する（誰の、どの情報が、いつから）
3. 〔ユーザーへの通知、監督機関への報告が必要かを確認する。専門家に相談する〕
4. 原因を直し、記録に残す

## 3. 決済まわり

| 状況 | 対応 |
|---|---|
| 支払いに失敗した | 〔決済サービスの自動再試行を待つ。失敗が続いたらメールで通知し、〇日後に停止〕 |
| 返金の依頼 | 〔[docs/legal/terms.md](legal/terms.md) の方針に従う。決済管理画面から返金する〕 |
| 二重請求 | 〔確認して即返金し、原因を調べる〕 |
| チャージバック（不正請求の申し立て） | 〔証拠を揃えて期限内に反論する。期限は決済サービスの案内を確認〕 |
| 解約の依頼 | 〔本人確認のうえ、管理画面から解約する〕 |

## 4. 問い合わせ対応

- 返信の目標：〔営業日1日以内など〕
- 返信テンプレートは「5. 返信テンプレート」を使い、状況に合わせて書き換える
- 繰り返し来る質問は、FAQ やアプリ内の説明に反映する
- 声は [docs/feedback.md](feedback.md) に記録する

## 5. 返信テンプレート

### 受付の連絡

> お問い合わせありがとうございます。〔サービス名〕の〔担当者名〕です。
> 内容を確認のうえ、〔営業日1日以内〕に改めてご連絡します。

### 不具合の報告を受けたとき

> ご報告ありがとうございます。ご不便をおかけして申し訳ありません。
> 現在、〔原因の調査／修正〕を進めています。〔回避策があれば記載〕
> 状況が変わりましたら、改めてご連絡します。

### 返金

> ご連絡ありがとうございます。〔日付〕のご請求について、返金の手続きをしました。
> 反映まで、カード会社により〔数日〜数週間〕かかる場合があります。

### 解約

> 解約の手続きが完了しました。〔支払い済みの期間の終了日〕まで、引き続きご利用いただけます。
> よろしければ、今後の改善のため、解約の理由をお聞かせいただけると助かります。

### 障害のお知らせ

> 〔日時〕より、〔影響の内容〕が発生しています。
> 現在、復旧作業を進めています。復旧しましたら、改めてお知らせします。
> ご迷惑をおかけし、申し訳ありません。
